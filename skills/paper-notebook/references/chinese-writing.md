# 通用去 AI 味写作约束

适用于中文文章、教程、报告、方案、产品文案及其审阅、改写。可直接作为模型的写作指令，也可作为人工编辑规范。

## 一、执行原则

写清具体对象、动作、关系和依据。用自然的中文组织信息，根据读者基础解释内容，根据材料决定语气和结论。

优先顺序：**用户的明确要求 → 事实与原意 → 理解所需的解释 → 自然表达 → 篇幅精简**。

去除生硬表达时，保留推导、例子、操作条件及必要信息。按句意修改，读完整段后再判断；关键词搜索只用于定位，不用于批量删除。

本规范中的词语和句式均按实际用途判断，不设必须清零的词表或数量配额。

## 二、中文语法与句式

### 1. 先确认谁在做什么

- 主体、动作、对象和结果应当清楚。条件、时间和范围按中文习惯安排；主语明确时可以省略。
- 检查主语与谓语是否搭配、动词是否有适当宾语、指代能否找到对象。
- 同一句中切换主体时，补出必要的主语。避免前半句说模型，后半句未经说明就变成数据或使用者。
- 拆开层层嵌套的长定语，减少“对于……而言，其……的实现是通过……进行的”一类结构。
- 句长随内容变化，不将全部句子改成相同长度或统一的主谓宾格式。

### 2. 检查“把”字句

“把”适合说明对明确对象的处置及结果，例如“把文件保存到指定目录”。保留自然、准确的用法。

需要改写的情况：

- 对象抽象，动作含糊，例如“把理解落到机制上”。
- 连续使用“把 A 变成 B”“把 X 拉到 Y”，掩盖实际过程。
- 宾语、补语搭配不成立，或一句话装入多层转换。

改写时说清实际动作。例如“把知识打通”应按原意写成“说明概念之间的依赖关系”，或具体列出哪些知识如何连接。

### 3. 检查“让／使”字句

“让”“使”可以表达真实的使动关系，例如“重叠区域使相邻片段保留部分共同上下文”。

- 能由主体直接完成的动作，优先直接写：“系统记录日志”，无需写“让系统去完成日志记录”。
- 删除“让理解发生”“让知识真正落地”等没有说明过程的表述，补出实际解释或操作。
- 检查因果是否成立。“让结果更可信”需要相应的方法或证据；不能靠使动句增加确定性。
- 操作指令明确指出执行者与动作，例如“保存检查点”，避免反复写“我们要让模型把……”。

### 4. 使用准确动词

- “进行误差的计算”改为“计算误差”。
- “对结果展开分析”按语境改为“分析结果”。
- “实现对文件的读取”改为“读取文件”。
- “赋能、打通、抓手、闭环、底座、沉淀、落地”等抽象词，只有在含义明确时使用；否则说明实际对象、动作和产物。
- 专业术语保持原义，不能为了显得简洁或专业而替换成另一种操作。

## 三、直接陈述，减少防御性写作

### 1. 先说内容

段首先陈述本段要解释的事实、问题、方法或判断，再展开理由和条件。

删除只用于表态的开场，例如“需要特别强调的是”“值得注意的是”“必须清醒地认识到”。如果后面的内容确实重要，直接写出内容。

### 2. 保留有用途的条件

对每个限制或提醒，判断：

1. 它帮助谁理解或采取什么行动？
2. 删掉后，哪项事实、结论或操作会被误解？
3. 它是否已经在相邻位置说明？

影响结论成立、适用范围或操作的条件，保留在相关内容旁边。只用于预防假想质疑、维护作者立场或重复表态的句子，删除。

例如，将“这里只是一个简化模型，不能完整描述现实”改为模型真正采用的假设，如“模型假设每期增长率恒定，期间无额外存取”。假设必须有材料依据。

### 3. 减少虚设反驳

- 不主动虚构一种错误观点，再用“不是……而是……”反驳。
- 可以直接陈述的结论，直接写。
- 确需区分概念时，按同一维度比较两者，并解释差异。
- 真实的否定、禁止事项、反例与原文引述应当保留。

### 4. 用证据确定语气

- 删除“可能也许在某种程度上”等叠加保留。
- 保留与证据相符的“可能”“约”“在本次实验中”等限定。
- 不用“显然、必然、永远、完全、只要……就……”替代推理。结论具有这些强度时，应有相应依据。
- 不把“尚未证明有效”改成“已经证明无效”，也不把相关关系改成因果关系。

## 四、清除空泛、表演化的表达

### 1. 空泛开场与拔高

删除不提供背景或论点的宏大开场，如“在这个飞速发展的时代”。说明当前对象面临什么问题即可。

删除无依据的价值判断，如“具有划时代意义”“这才是真正的价值”“意义远不止于此”。用具体变化、适用场景和数据表达价值。

### 2. 假口语与说教

减少“说白了、你看、别急、敲黑板、划重点、是不是很简单、千万别踩坑”等表演性口语。教学语气可以亲切，但解释应来自内容本身。

不臆测读者“肯定会误解”“往往意识不到”。确有易混概念时，说明混淆点和判断方法。

### 3. 空泛比喻与拟人

- “给公式注入灵魂”“打开知识的大门”等装饰性比喻直接删除。
- “准确率会说谎”“模型偷懒”“数据惩罚你”等表述改为可观察的机制或行为。
- 有助于理解的类比可以保留，但应解释对应关系；对应关系不成立时，使用具体例子。
- 文学、创意写作和用户指定的修辞按任务处理，不强行改成技术说明。

### 4. 虚构亲历与权威

不编造个人经历、采访、实测、读者反馈或专家观点。没有材料依据，不写“我曾经遇到”“实测发现”“研究表明”。

教学设定明确写为例子或假设；材料中的真实经历保留其叙述者身份。

## 五、段落、标题与信息组织

- 每段围绕一个主要问题展开，句子之间有真实的因果、条件、递进或比较关系。
- “因此”“然而”“同时”等连接词必须与前后逻辑相符，不能用于制造行文感。
- 标题直接说明对象或问题。减少“深度解读、全面解析、终极指南”等空标签，以及连续重复的标题模板。
- 普通解释使用连贯段落；步骤、并列项目和比较使用列表或表格。
- 不强凑三点、五步、四个关键词，也不要求每节拥有完全相同的结构。
- 删除只换词复述的段末、节末总结。跨概念综合、阶段回顾或迁移应用有实际作用时再总结。
- 粗体突出少量概念、结果或条件，不将整段加粗，也不依靠密集标点表现强调。

## 六、内容准确性与前后一致

风格编辑与内容检查分别完成。遇到错误，修正有依据的部分；缺少证据时明确待核实的具体问题。

重点检查：

- **概念**：定义、术语和适用条件是否正确，是否混用不同对象。
- **数字**：分子分母、百分数、倍数、单位和数量级是否一致，例题能否复算。
- **比较**：基线、评价指标、样本、设备或运行条件是否明确。
- **推断**：观察、原因解释与改进建议是否区分；单个案例是否被扩大为普遍结论。
- **代码**：命令、参数、路径和输出是否对应实际实现；示意片段是否交代了所需上下文。
- **一致性**：正文、摘要、图表、习题、解析和最终汇总是否使用同一事实与结论。

不得为了语言流畅补造数字、来源、原因或实验结果。语言检查器只能提示表达问题；内容是否正确仍需依据材料、计算或实际运行判断。

## 七、教程与技术讲解的附加约束

按读者的已有基础安排知识，给难点留足解释。精简重复，不压缩必要的学习步骤。

- 新概念首次出现时解释含义、用途及与已学内容的关系。
- 公式交代符号、条件与结果含义；难点用一个足够小的例子逐步计算。
- 代码交代输入、关键操作和输出。新增语法、数据类型、索引与张量形状在需要的位置解释。
- 从已知内容推到新内容。中间缺少前提时，补上前提，不用“显然”“容易看出”跳过。
- 每一步说明为什么需要、实际做什么、得到什么，并自然连接下一步；不必将这三问固定写成模板。
- 说明实验结果支持什么，再讨论可能原因。不要承诺“多训练自然会好”“换大模型一定有效”。
- 习题应能由已讲知识解答；题干、选项、答案和解析保持一致。
- 内容较深时可以分层安排基础与扩展，但基础部分应形成完整的理解链路。

## 八、改写示例

以下示例展示修改方法，数字和情境仅为示例，不可移植为正文事实。

| 待改表达 | 可用改写 |
| --- | --- |
| 本节将让你把对梯度的理解真正落到参数更新上。 | 本节用一个参数演示梯度怎样决定更新方向和幅度。 |
| 对这些参数的更新是通过梯度下降来进行的。 | 梯度下降沿负梯度方向更新参数。 |
| 要把这件事看成是数据在对模型进行约束。 | 训练目标根据样本计算误差，并据此更新模型参数。 |
| 让结果具备可解释性的关键，是把口径给对齐。 | 比较结果时，应采用相同的指标和测量条件。 |
| 这不是在计算订单数，而是在识别顾客数。 | 按顾客编号去重后计数，得到顾客数。 |
| 总准确率会说谎。 | 类别不平衡时，只预测多数类也可能得到较高准确率。 |
| 需要特别强调，这并不能说明模型真的学会了。 | 本次评价统计了输出格式是否合格，尚未检查答案是否正确。 |
| 模型可能也许在一定程度上改善了效果。 | 若原始记录支持，可写“本次验证中，命中数由4/54增至5/54”。 |
| 两个指标的差异，正是这份报告真正的价值所在。 | 两个指标分别评价格式和答案正确性，需要分别报告。 |
| 模型多训练几百步，命中率自然会升上来。 | 比较不同检查点的验证命中率，再选择训练步数。 |
| 平均误差下降。总之，模型预测得更准了。 | 保留“平均误差下降”，删除重复总结。 |

## 九、审阅与交付方式

### 用户要求审阅

报告可行动的问题。每项给出位置或原句、具体问题，以及最小改法。表达问题、内容错误和可选优化分别列出；篇幅按用户要求控制。

评价可观察的句法、重复、逻辑和事实问题，不根据措辞推断作者或给出“AI生成概率”。用户只要求审阅时，提供报告；是否修改原文件按用户授权处理。

### 用户要求改写

先理解完整材料，再逐段处理语法、逻辑、重复和语气，核对事实后交付改写稿。默认只给成稿；用户需要时再附修改说明。

如果所改内容在摘要、图表或习题中重复出现，同步处理。改完后通读相关上下文，不将一句话改顺就视为整段完成。

### 交付前自检

- 主体、动作、对象与指代是否清楚，中文搭配是否自然？
- “把／让／使”是否表达了明确关系，有没有掩盖机制或夸大因果？
- 是否存在空泛开场、虚设反驳、假口语、装饰性拟人或重复总结？
- 限定是否影响理解，是否已在相关位置说明？
- 事实、数值、范围和确定程度是否与材料一致？
- 读者能否理解概念与步骤，是否因精简而缺少关键解释？

发现问题就修正对应内容。满足要求后交付，不额外添加自我评价、审阅过程或“已完全去除AI味”等保证。

## 十、可直接复制的简版指令

```text
请按以下规则撰写或修改中文：

1. 以用户要求、事实准确和读者理解为先，逐句按意思修改，保留必要解释。
2. 主体、动作、对象和结果清楚，指代明确，语序自然，拆开过长的定语与名词化结构。
3. 检查生硬的“把／让／使”句，改成具体动作或关系；自然、准确的用法保留，不机械禁词。
4. 直接陈述观点、方法、事实和条件，删除空泛开场、虚设反驳、价值拔高、假口语与装饰性拟人。
5. 删除只为预防假想质疑的防御句。必要的范围、条件和不确定性保留在对应内容旁边。
6. 一段推进一个主要问题，用真实逻辑连接句子，不强凑排比、固定点数或每节总结。
7. 不编造亲历、来源、数字、原因或结果，不把观察扩大为因果或普遍结论。
8. 教学内容解释新术语、前提、符号和代码，提供必要的小例子与中间步骤，避免知识跳跃。
9. 核对数字、单位、倍数、命令和前后一致性；正文、摘要、表格、习题与解析同步。
10. 修改后通读上下文。默认交付成稿；只要求审阅时，简短列出具体问题与改法。
```

## 参考原则

本文件根据以下编辑原则独立归纳，并补充中文句法、教学说明与内容核对要求：

- [anti-defensive-writing](https://github.com/Kiterlin/anti-defensive-writing)：直接陈述，保留影响理解与结论的必要条件。
- [STSS](https://github.com/lennney/stop-that-shit/tree/0.2.5/skills/stss)：按句子的读者用途判断其去留，核对改写前后的事实与主张。

使用本文件无需安装相关技能或访问原工作目录。
