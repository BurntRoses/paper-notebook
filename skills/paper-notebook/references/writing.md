# 教材编写与内容验收

产物是可以独立学习的教材式电子笔记。先确定学习目标、先修关系、覆盖范围和可用时长，再按“问题 → 概念与条件 → 解释或推导 → 完整例题 → 适用边界 → 章节联系”建立内容路径。短篇也应闭合一个问题；长期课程需要章节依赖、术语一致性和可追踪的进度。时间少时缩小范围，不用删去关键理由来假装讲完一门课。

## 概念、例题与练习各司其职

- `concept`：给出准确的定义、符号、单位、适用条件和必要的边界。概念首次出现时解释，后文沿用同一术语；不要用一个口号代替定义。
- `prose`：承接因果、解释“为什么”，连接前后知识。普通解释保持连续文字，不将每句话装成一张卡片。
- `formula` 与 `steps`：逐步列出变换和理由，交代使用的定理或假设。重要公式单独占块，推导可分为若干完整阶段；不把半个等式推到下一页。公式下方使用 `parameters: [{symbol,name,description}]` 逐项解释符号，每项单独一行，写清含义、单位、条件、参数变化或具体数值；整体假设放 `text`。函数至少搭配一种有解释作用的坐标图、计算路径或数值对照，帮助读者对应输入、运算与输出。
- `example`：明确“教学例题”，完整写出已知、求解目标、每一步的依据、计算和结论；自拟数值标明教学用途。后续案例可沿用同一对象，逐步增加复杂度，避免一章换三个无关故事。
- `comparison`、`chart`、`diagram`：承担对比、数据或结构的解释，图后说明读法和结论。图文中的变量、计数、方向与数值必须一致。
- `exercise`：只有用户选择需要练习时使用；题目、提示与解析区分，不把带答案的例题伪装成练习。主观题使用参考要点，不自动判分。

篇幅随范围调整。通常 30–45 分钟的系统导读应有若干章节和约 8–16 张内容纸页，每页聚焦一个可讲清的问题；深入课程可以分册。这个范围是容量参考，不是凑页数指标。不要用十几个小标题、每节两句话冒充完整教材。交付前检查每个目标是否有定义、解释、完整例子或直接证据支撑；明确没有覆盖的主题与下一步先修关系。

## 有解释力的图文，而非装饰

对空间、数值、流程、分类、比较等视觉上更清楚的内容，主动提供实际图解。系统教程通常每一至两页有一幅承载知识的图、数据图、对照表或带标注示意；不要求每页插图，也不重复同一种三框箭头图。机器学习可组合：样本散点与预测直线、误差残差、训练与验证流程、复杂度与泛化、算法对照表。

优先可编辑的原生 SVG、`diagram`、`chart` 和表格。允许检索可靠互联网资料获取依据和可复用素材，或自行绘制手绘风格的解释图。技术几何与数值必须准确，手绘只影响线条与图框。照片、复杂生物形态等使用带来源和许可的图片；图片内嵌，并提供说明与 alt。不要写“此处插入图片”却不交付图片，不把外链图片算作离线资产。没有检索能力时说明限制并使用可核实知识与原创图解，不编造来源。

## 纸页组织

默认 `cornell`：正文区用于讲解，侧栏 `cues` 写与本页真实块相连的关键词或回忆问题，底栏 `summary` 写条件、关系或迁移结论。不要在每页复制同一句“你学会了吗”。单幅大图、长推导或宽表可以改为 `reading`，充分使用横向宽度；复杂内容宁可另起一页，也不要缩成小字或塞进窄栏。避免过长页标题。

通过 `study.role` 标识定义、直觉、推导、例题、证据、要点或回忆；`study.frame` 可选 plain/pencil/tape/double/margin，或 auto 由阅读器按稳定 ID 分配。相同类型与章节保持节奏，变化服务于辨识。少量圈注、旁注和黑板强调真正需要记忆的原句，避免整段高亮。

圈点勾画属于默认作者排版，需要在源数据中明确写出 `study.marks`，阅读器不会自动挑选重点。按内容选择：核心术语用 `circle`，关键条件用 `underline`，决定性词句用 `dots`，已推导出的结论用 `check`；荧光、波浪、框选、括注和星标按需使用。普通讲解页通常选一至三处短语即可，封面、目录、来源页和纯图页无需硬凑；不要要求每页九种齐全。用户明确要求无圈画时才省略作者标记。

例如 `{"id":"growth-key","type":"prose","text":"复利以每一期的期末值作为下一期的基础。","study":{"marks":[{"text":"期末值","kind":"circle"},{"text":"下一期的基础","kind":"underline"}]}}`。`text` 必须是实际组件正文的完整、非空子串；不要用标题中的词去标记正文，不要用 Markdown 粗体、emoji 或图片中的笔画冒充原生标记。作者标记属于正文 `study.marks`，不可仅存在于个人 `userState.annotations` 中。交付前检查构建报告中的作者标记数量、类型和未标记页，并在实际离线成品上确认可见。

## 表达与事实

直接解释具体对象、动作、条件和结果。保留准确术语、否定、不确定性和来源位置。例题逐步列出数值、理由和单位。引用不足时写明待核实；不虚构个人经历，不预设读者理解有误，不凭空添加“常见误区”。避免对话开场、空泛鼓励、装饰标签、机械排比和反复总结。

一般避免“把”“被”“让……”和“不是……而是……”等重复句式；准确引文、术语和必要的技术语言不受限制。自然表达优先于生硬避词。参考 Humanizer / Humanizer-zh 的事实边界与套话清理原则；来源和 MIT 声明保留在工具包 licenses 中。

交付前检查：目标覆盖 → 先修链 → 定义/例题/练习区分 → 数值与推导 → 图文一致 → 作者圈点的原句锚点及实际显示 → 来源与未覆盖范围 → 横竖屏排版。没有实际检查的项目明确列出，不声称已通过。
